MERCHANT SAATHI - TEAM CONTEXT PACK
07-CONVENTIONS (rules that keep us out of trouble)
================================================================================

MONEY
  1. All amounts are INTEGER PAISE everywhere (DB, API, calculations).
     Rs 70 = 7000. If you typed a float, stop.
  2. Formatting only at the UI edge: formatINR(paise) in src/lib/money.ts (server)
     and src/lib/format.ts (client). Indian digit grouping, en-IN.
  3. The AI never computes money. computeOffer() in src/domain/offers.ts is the
     only place offer economics exist. Do not duplicate that math.

TIME
  4. Store UTC ISO strings. Reason about business time in IST via src/lib/clock.ts
     (fixed +05:30 offset - do NOT add a timezone library for this prototype).
  5. Afternoon windows = UNION of five daily 15:00-18:00 IST bands.
     Use completedAfternoonTotals(), never a continuous start/end range.
  6. Never compare a partial current day against a complete historical day.

DATA HONESTY (the USP - guard it)
  7. Every number shown must trace to a metric id / evidence entry / computed
     field. No hand-drawn values in charts.
  8. Keep the labels: "Synthetic demo data", "Simulated campaign outcomes",
     AI mode badge (fixture/live/fallback). Never say "send" - it is
     "Queue simulated campaign".
  9. The product may say "insufficient data". Keep that path working.
 10. No causal claims: orders "fell", NOT "because of weather/competition".
     No open rates, no lift %, no invented market size.

VALIDATION & ERRORS
 11. Every API route: Zod-parse the body (src/lib/validation.ts), throw ApiError
     with a code from src/lib/errors.ts. Never return raw exceptions.
 12. Tenant identity comes from the session cookie ONLY. A client-supplied
     business id (x-merchant-id) is a SELECTOR, not an authorization: it is
     honored only when the merchant row belongs to this session
     (resolveMerchant). Every query filters by merchant_id. Client
     idempotency keys are stored per merchant (req:<merchantId>:<key>).
 13. Never log or return stack traces to the client; log server-side instead.

AI SAFETY (src/adapters/ai.ts, src/lib/saathi-brain.ts)
 14. Evidence ids from the model are checked against EVIDENCE_IDS allowlist.
 15. Generated copy passes copyMonetaryTermsValid() or we fall back to the
     reviewed template (and say so).
 16. Live calls: 15s timeout, max ONE retry, server-side key only. The
     endpoint host is validated first (public http(s) only - no localhost,
     private IPs, encoded addresses or redirects) and DATABASE_PATH is
     validated too (project-relative only). Keep tests/security-guards.test.ts
     green when you touch either.
 17. No customer identifiers or raw order rows ever go into a prompt.
 18. The chat assistant plays by the same rules: answers only from
     buildAssistantFacts() (the same domain functions as the screens); live
     replies pass the rupee-token guard (assistantMonetaryTermsValid) or fall
     back to the fact book with a labeled note. The key from the brain dialog
     lives in server memory only (assistant-settings.ts) - never on disk,
     never in the DB, never returned unmasked.

UI, MOTION & SOUND
 19. Every chart value comes from a computed DTO (GroupedBars/Meter/Donut/
     Waterfall take numbers from the API responses - no hand-drawn values,
     no chart libraries needed; src/components/charts.tsx).
 20. Animation lives in globals.css as ms-* keyframes, honors
     prefers-reduced-motion, and never animates layout-critical properties
     of the hero flow. Mascot moods: idle/happy/exited... see mascot.tsx.
 21. Sounds are synthesized (src/lib/sound.ts). Keep peaks low; never block
     an interaction on audio; the mute toggle must always work.
 22. Mascot speech is prose, not data: it must NOT echo exact asserted
     strings (the e2e uses strict locators like /below the 25% floor/i -
     duplicating them in a bubble breaks strict mode). Reference the banner
     instead of quoting it.
 23. New tour steps need a [data-tour="..."] attribute on a stable element.
 24. Schema migrations must suspend foreign keys around any DROP/RENAME
     (better-sqlite3 runs with FKs ON; a parent-table drop under FK
     enforcement CASCADE-deletes every child row). openDatabase also prunes
     childless merchant husks so broken migrations self-heal.
 25. New UI strings must not duplicate text the e2e asserts (strict locators).
     Check tests/e2e/merchant-flow.spec.ts before naming headings/labels.
 26. Client requests self-heal a stale business selector (one 404 retry
     without the header). Do not "fix" the 404 away server-side: foreign ids
     must still be refused.
 27. The operations copilot is ADVISORY: it computes run-rates, cover and
     restock plans from real rows and never mutates inventory or places
     orders. Any automation idea goes through the owner first.
 28. Domain fixtures change names only - the numeric blocks are shared and
     anchored by fixtures:verify (see file 04 golden rule).

TESTING
 24. If you change money/consent/approval/idempotency logic, add or update a
     Vitest test. Look at tests/approval.test.ts for the expectApiError pattern.
 25. Tests use their own tenants (freshTenant / queuedCampaign helpers) on
     data/test.sqlite. Do not point tests at the demo DB.
 26. Run the full check list (file 05) before pushing.

CODE STYLE
 27. TypeScript strict; no `any` unless truly unavoidable (and then comment why).
 28. Routes thin, services fat, domain pure. Match the existing naming.
 29. UI: Tailwind classes inline; reuse Card/Badge/Stat/Alert from
     src/components/ui.tsx. Large touch targets, readable contrast, rupee
     formatting everywhere.

GIT
 30. Branch per task: t<initials>-<topic> e.g. tA-live-ai-smoke.
 31. Commit messages: imperative, one topic ("Enforce cap atomically in redeem").
 32. Never commit: .env.local, data/*.sqlite*, node_modules, screenshots with
     secrets, or local tool artifacts (e.g. a .mimosa/ folder). .gitignore
     already covers the common cases - keep it that way.
 33. PR into main; another teammate reviews; integrate every 60-90 minutes.
