MONEY RULE: every amount is an INTEGER number of PAISE. Rs 70 = 7000.
Never store floats. Format only at the UI edge (src/lib/money.ts).

TABLES (schema auto-created on first connection; see src/lib/db.ts)
  merchants(id PK, demo_session_id UNIQUE, display_name, timezone, currency,
            fixture_version, created_at)
  orders(id PK, merchant_id FK->merchants CASCADE, external_id, occurred_at UTC,
         status CHECK completed|pending|canceled, total_paise,
         UNIQUE(merchant_id, external_id))
  order_items(id PK, order_id FK->orders CASCADE, sku_id, quantity>0,
              unit_price_paise, unit_discount_paise DEFAULT 0)
    INVARIANT: SUM(quantity*(unit_price - unit_discount)) == orders.total_paise
  inventory(merchant_id+sku_id PK, quantity>=0, unit_variable_cost_paise NULLABLE,
            version, updated_at)
    NULL cost means UNKNOWN - never zero. version bumps invalidate approvals.
  customers(id PK, merchant_id, demo_channel_id, display_label)
    ids look like "mrc_<session>_CUST-001" (tenant-scoped!)
  consents(id PK, customer_id, channel, status active|revoked|none,
           captured_at, source, revoked_at, UNIQUE(customer_id, channel))
  metric_snapshots(id PK = "<merchant>_<evidence-id>", ..., values_json)
  campaigns(id+version PK, merchant_id, status draft|approved|queued,
            opportunity_id, offer_json, copy_json, audience_hash, audience_count,
            inventory_version, metric_snapshot_id, preview_hash, expires_at,
            ai_mode, created_at)
  approvals(id PK, campaign_id, campaign_version, approver_id,
            approved_payload_hash, approved_at)
  outbox(id PK, campaign_id, version, customer_id, channel,
         status 'simulated_queued', simulated=1, idempotency_key UNIQUE,
         UNIQUE(campaign_id, version, customer_id, channel))
  redemptions(id PK, campaign_id, event_id, quantity, amount_paise, occurred_at,
              simulated=1, UNIQUE(campaign_id, event_id))
  idempotency_requests(key PK, fingerprint, response_json, created_at)
  audit_events(id PK, merchant_id, actor_id, action, entity_id, timestamp,
               redacted_details_json)

LIFECYCLE SEMANTICS (what makes this defensible)
  DRAFT     POST /api/campaigns/draft creates a NEW version (same campaign id
            on edit). Stores computed offer + copy + audience_hash +
            inventory_version + preview_hash (sha256 of id/version/price/cap/
            audienceHash/inventoryVersion/expiresAt).
  APPROVE   Recomputes audience hash and inventory version; compares client
            previewHash with stored; refuses unprofitable offers (re-runs
            computeOffer). Any mismatch -> 409 stale_preview. Writes approval
            row + flips status.
  EXECUTE   Rechecks: latest version only, approval matches hash, now <
            expires_at, inventory_version unchanged, audience hash unchanged.
            Then, inside BEGIN IMMEDIATE: inserts 40 outbox rows (per-recipient
            idempotency key = sha256(campaign:version:customer:channel)),
            flips status to 'queued'. Repeats return the ORIGINAL receipt
            (duplicate: true). A reused client key with DIFFERENT input -> 409.
  REDEEM    Only fixture event ids (R-001..R-010). Replay of the same event ->
            existing record, duplicate: true. Cap enforced by COUNT inside the
            transaction. Amount must equal approved price x quantity. Stock is
            re-checked cumulatively per component.
  RESULTS   Computed live from redemptions: revenue = SUM(amount),
            cost = quantity x bundleCost, contribution = revenue - cost,
            discount = (normalPrice - price) x quantity.

ENDPOINTS (all session-scoped; JSON)
  GET  /api/demo/state
       -> { seeded, sessionId, merchant?, nowIso, clockInjected, aiMode,
            kpis { previous{label,orders,netSalesPaise,aovPaise}, current{...},
                   ordersDeltaPct, salesDeltaPct }, audience{eligible,excluded} }
  POST /api/demo/reset
       -> reseeds THIS session's tenant; { fixtureVersion }
  GET  /api/opportunities
       -> { items: [ { id, observation, metricIds, limitations, windows,
                       suggestedOffer, evidence[] } ], lowDataReason?,
            eligibility { previousOrders, currentOrders, minOrdersRequired,
                          declinePct, declineThresholdPct } }
  POST /api/campaigns/draft
       body { campaignId?, opportunityId, offer { pricePaise, cap }, locale?,
              copyOverride? { title, body } }
       -> 201 { campaignId, version, status:"draft", offer, computed,
                headline, explanation, assumptions, copy, copySource, aiMode,
                aiNote?, evidence[], evidenceIds, audience, expiresAt,
                validityLabel, previewHash }
       NOTE: a draft is returned even when computed.passes=false so the UI can
       show WHY it fails (like the Rs 50 row in our slide). Approval refuses it.
  POST /api/campaigns/{id}/approve
       body { version, previewHash } -> 201 { approvalId, approvedVersion }
       | 409 stale_preview / stale_version | 422 business_rule
  POST /api/campaigns/{id}/execute
       body { version, idempotencyKey? }
       -> 201 { status:"simulated_queued", count, receiptId, duplicate }
       | 409 | 422 stale_inventory / stale_consent / expired
  POST /api/demo/campaigns/{id}/redeem
       body { eventId: "R-001" } -> 201 { redemption{duplicate?}, totals, cap }
       | 404 unknown event | 422 cap_reached / business_rule
  GET  /api/campaigns/{id}/results
       -> { campaign{...}, outbox{queued, sample[]}, redemptions{...},
            availableEvents[], auditTrail[], caveats[] }

POST /api/assistant/chat       body { question (2-500 chars) }
     -> 200 { answer, reasoning[], followUps[], mode: live|fixture|fallback,
              note?, intent? }
     Grounded: answers are built from the session's computed facts (fact book)
     or, with a live brain key set, from a model reply that passed strict JSON
     validation + the rupee-token guard (every amount must exist in the
     computed facts; violations fall back to the fact book with note).

GET/POST/DELETE /api/assistant/settings
     GET    -> { configured, maskedKey, model, baseUrl, setAtIso } - masked only
     POST   -> { apiKey, model, baseUrl? } stored in server MEMORY for the
               process (never disk, never DB); endpoint must pass the same
               public-host validation as the live draft adapter
     DELETE -> clears the in-memory key
     No UI string ever contains the raw key.

ERROR ENVELOPE (every failure looks like this)
  { "error": { "code": "stale_preview", "message": "...",
               "fieldErrors"?: {...}, "retryable"?: bool } }
  Codes -> status: invalid_input 400, missing_session 401, disallowed 403,
  not_found 404, stale_preview/stale_version/conflict 409, business_rule /
  stale_inventory / stale_consent / expired / cap_reached 422, rate_limited 429,
  ai_unavailable 503. Never leak other tenants' existence; never return stacks.

COMMON 409 SITUATIONS (by design - explain, don't "fix")
  - "Terms changed since this draft" -> you edited price/cap after drafting;
    press "Update draft (new version)" to bind a fresh preview.
  - "A newer draft version exists" -> old versions are superseded; work with
    the latest.
  - "Stock/consent changed since approval" -> something mutated the facts the
    approval was based on; make a fresh draft + approval. This is the whole
    point of the control loop.
