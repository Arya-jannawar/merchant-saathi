MERCHANT SAATHI - TEAM CONTEXT PACK
05-SETUP-AND-COMMANDS
================================================================================

PREREQUISITES
  - Node.js 20 or newer (LTS recommended; we verified on Node 24.11).
    Check: node --version
  - Git. That is all - no Python, no Visual Studio build tools.
    (better-sqlite3 ships prebuilt binaries for LTS Node versions.)

FIRST-TIME SETUP (PowerShell or Git Bash, from the repo root)
  git clone https://github.com/Arya-jannawar/merchant-saathi.git
  cd merchant-saathi
  npm install
  copy .env.example .env.local        (PowerShell)
  cp   .env.example .env.local        (Git Bash)
  npm run db:seed
  npm run fixtures:verify
  npm run dev
  -> open http://localhost:3000/merchant and click "Load sample data"

  `npm run fixtures:verify` MUST print "All fixture checks passed." before you
  trust anything you see. It is our reconciliation gate - run it after pulling.

ENVIRONMENT (.env.local - never commit it)
  DATABASE_PATH=./data/merchant-saathi.sqlite
  AI_MODE=fixture            # or "live" (needs the two Z.ai vars)
  ZAI_API_KEY=               # standard Z.ai application API key (server-side only)
  ZAI_MODEL=                 # e.g. your account-supported model id
  ZAI_BASE_URL=https://api.z.ai/api/paas/v4
  DEMO_MODE=true             # pins the clock to Fri 6 Nov 2026, 7:00 PM IST
  DEMO_NOW=                  # optional explicit ISO override

  No NEXT_PUBLIC_ vars exist on purpose - nothing about the DB or AI belongs
  in the browser bundle.

ALL COMMANDS (npm scripts)
  npm run dev              dev server on :3000 (hot reload)
  npm run build            production build
  npm start                production server (run build first)
  npm run lint             ESLint (next/core-web-vitals)
  npm run typecheck        tsc --noEmit (strict)
  npm test                 Vitest unit tests (78 tests)
  npm run test:watch       Vitest in watch mode
  npm run test:e2e         Playwright hero-path flow (run npm run build first;
                           first run downloads Chromium ~130 MB; starts its own
                           server on :3100 with an isolated DB state)
  npm run db:seed          seed ./data/merchant-saathi.sqlite (safe to re-run)
  npm run fixtures:verify  reconcile every fixture number (exit 1 on mismatch)

FULL CHECK LIST BEFORE ANY DEMO OR PR
  npm run fixtures:verify  &&  npm test  &&  npm run lint  &&  npm run typecheck  &&  npm run build
  (Optionally: npm run test:e2e)

DATABASE FILES
  data/merchant-saathi.sqlite   your local demo DB (git-ignored)
  data/test.sqlite              unit-test DB (git-ignored)
  Delete either file any time; everything is regenerated by seed/tests.

TROUBLESHOOTING (Windows)
  Dev server shows "Server Error: Cannot find module './276.js'" (any chunk number)
    -> You (or a teammate) ran `npm run build` while `npm run dev` was running.
       Both share the .next folder; the build clobbers the dev cache.
       Fix: stop dev (Ctrl+C), delete .next, run `npm run dev` again.
       Rule: NEVER build while dev is running - use `npm test` +
       `npm run fixtures:verify` for quick checks instead.
  "better-sqlite3 was compiled against a different Node.js version"
    -> You switched Node versions. Run: npm rebuild better-sqlite3
    -> If that fails: delete node_modules + package-lock.json, npm install again.
  Port 3000 busy
    -> npm run dev -- -p 3001   (or kill the old process)
  fixtures:verify FAILs
    -> Do not edit the script to make it pass. Delete data/*.sqlite, re-run
       db:seed, re-verify. If it still fails, someone changed code or fixture
       numbers - check git diff before "fixing" anything.
  The dashboard says "Load sample data" forever
    -> Check the browser kept cookies (httpOnly session). In incognito, load
       the data again - each browser session is a separate tenant by design.
  Approve returns 409 stale_preview
    -> Expected if you edited price/cap after drafting. Press
       "Update draft (new version)", then approve the fresh preview.
  Playwright times out waiting for :3100
    -> Run `npm run build` first; check nothing else is bound to port 3100.

USEFUL VERIFICATION (what the flow should look like)
  1. Dashboard: 100 -> 70 orders, Rs 8,000 -> Rs 5,600, -30.0% badges.
  2. Offer workspace: default Rs 70 / cap 20 -> "Passes the 25% margin floor",
     margin 42.9%, capacity 25, exposure Rs 400. Try Rs 50 -> red violation,
     Approve disabled. Restore Rs 70.
  3. Approve -> "approved (timestamp)" -> "Queue simulated campaign" ->
     "View campaign activity (40 recipients)".
  4. Campaign page: "Apply all 10 events" -> Rs 700 - Rs 400 = Rs 300 panel.
     "Re-apply R-003" -> "changed nothing (idempotent)".
